MCP: Битрикс24, 1С, SuperGrok, Codex, Claude Code — разбор (16.10.2026)

Главное. Для Битрикс24 есть официальный MCP-сервер с доступом к CRM. Для 1С официального сервера нет, есть сторонние серверы через OData. Все три клиента (Grok, Codex, Claude Code) умеют подключать MCP. Связку Битрикс24 ↔ 1С лучше строить на штатном «Коннекторе к 1С», а MCP использовать для работы агента.

Все ссылки проверены 16.10.2026 (ответ 200).

1. Системы

1.1. Битрикс24

  1. Официальный рабочий сервер: https://mcp.bitrix24.com/mcp/. Он даёт доступ к CRM, задачам, структуре компании, приглашениям и почте. Права — как у сотрудника. Источник: https://helpdesk.bitrix24.com/open/25866707/
  2. Включение: администратор открывает «Настройки → MCP-серверы» и включает «Разрешить подключение внешних ИИ». По умолчанию доступ выключен. Источник: там же.
  3. Вход: OAuth или токен из «Приложения → MCP-подключения». Источник: там же.
  4. Сервер документации: https://mcp-dev.bitrix24.com/mcp. Он без входа, протокол Streamable HTTP. Он только ищет методы REST и не трогает данные портала. Источники: https://apidocs.bitrix24.ru/ai-tools/mcp.html , https://github.com/bitrix24/mcp-rest-doc
  5. Шаблон своего сервера: bitrix24/templates-mcp. Сейчас в нём 29 инструментов, почти все про задачи. CRM в нём пока нет. Источник: https://github.com/bitrix24/templates-mcp
  6. Воронки через REST. Воронки — это направления сделок: crm.category.list с entityTypeId=2. Стадии — crm.status.list. Сделки — crm.item.* или crm.deal.*. Перенос в другую воронку — crm.item.update с categoryId. Источник: https://apidocs.bitrix24.ru/api-reference/crm/deals/index.html
  7. Анализ воронок. Агент читает сделки и стадии и считает конверсию сам. Готового инструмента «анализ воронки» в источниках я не нашёл.
  8. Ограничения:
  9. Справка по рабочему серверу опубликована на домене .com. Работу с порталами .ru нужно проверить на своём портале.
  10. Точный список инструментов CRM в справке не приведён. Его видно после подключения.
  11. Стоимость в справке не указана.

1.2. 1С (Бухгалтерия, УНФ, УТ, ERP)

  1. Официального MCP-сервера от фирмы «1С» я не нашёл.
  2. Основа всех сторонних серверов — стандартный интерфейс OData базы 1С. Его включают при публикации базы на веб-сервере.
  3. Сторонние серверы:
  4. evilbruce666/1c-odata-mcp. Поиск контрагента по названию и ИНН, карточка, создание контрагента, счёта и контактного лица. Чтение по умолчанию, запись с предпросмотром. Работает с облаком 1cFresh. Источник: https://github.com/evilbruce666/1c-odata-mcp
  5. theYahia/aprovodka (прежнее имя 1c-rest-mcp). 34 инструмента: справочники, документы, регистры. Создание и изменение элементов справочника. Три режима защиты записи. Установка в базу не нужна. Источник: https://github.com/theYahia/aprovodka
  6. pyrfor/onec-odata-mcp. Чтение и описание сущностей. Запись — только с флагом ONEC_WRITABLE=true. Источник: https://github.com/pyrfor/onec-odata-mcp
  7. Имена справочников разные. В Бухгалтерии и УНФ — Catalog_Контрагенты. В УТ 11 клиент — Catalog_Партнеры. Источник: README серверов выше.
  8. Ограничения:
  9. Серверы сторонние, без гарантий. Нужен свой аудит кода.
  10. Вход в 1С — логин и пароль (Basic). Нужен отдельный пользователь с узкими правами.
  11. Облачные клиенты (Grok, claude.ai) требуют публичный адрес сервера. Базу 1С нельзя открывать в интернет без защиты.

2. Связка Битрикс24 ↔ 1С

  1. Основной путь — штатный обмен. В Битрикс24 ставят приложение «Коннектор к 1С». В 1С ставят расширение «Коннектор к Битрикс24». Источники: https://helpdesk.bitrix24.ru/open/26617332/ , https://helpdesk.bitrix24.ru/open/21050470/
  2. Что умеет штатный обмен:
  3. Двусторонний обмен контрагентами, контактами и товарами.
  4. Синхронизация сделок и заказов по расписанию.
  5. Поиск клиента 1С по ИНН из Битрикс24.
  6. Роботы: смена стадии сделки создаёт документ в 1С.
  7. Ограничения штатного обмена:
  8. Товары из сделки в 1С не передаются.
  9. Контрагент создаётся только при точном совпадении названия или ИНН.
  10. Заказ в 1С нужно провести, иначе синхронизации нет. Источник: https://helpdesk.bitrix24.ru/open/21050470/
  11. Воронки и стадии. Стадии сделок сопоставляют в 1С по каждому направлению. Источник: https://dev.1c-bitrix.ru/learning/course/?COURSE_ID=48&LESSON_ID=22866
  12. Роль MCP. Агент держит два сервера: Битрикс24 и 1С. Он не заменяет обмен, а работает поверх него.
  13. Операции агента:
  14. Найти клиента в 1С по ИНН. Создать или обновить компанию в Битрикс24.
  15. Создать сделку в нужной воронке и стадии.
  16. Сверить: компании без ИНН, дубли, сделки без контрагента в 1С.
  17. Построить отчёт по воронке: сделки по стадиям, зависшие сделки.
  18. Правила против конфликтов:
  19. Один главный источник для каждого поля. Реквизиты (ИНН, КПП, счёт) — 1С. Воронка и стадии — Битрикс24.
  20. Ключ сопоставления — ИНН и КПП, для физлиц — почта или телефон.
  21. Каждая запись агента — сначала предпросмотр, затем «да» человека.
  22. Внешний код 1С хранить в поле карточки Битрикс24.

4. Шаги для старта (бюджет — около 0 ₽ сверх текущих подписок)

  1. Включите MCP в Битрикс24: «Настройки → MCP-серверы».
  2. Получите токен в «Приложения → MCP-подключения».
  3. Подключите https://mcp.bitrix24.com/mcp/ в Claude Code или Codex.
  4. Проверьте чтение: список воронок и стадий сделок.
  5. Создайте тестовую компанию и тестовую сделку. Затем удалите их вручную.
  6. Опубликуйте копию базы 1С с OData. Используйте отдельного пользователя только с чтением.
  7. Поставьте aprovodka или 1c-odata-mcp локально (stdio). Режим записи пока выключите.
  8. Проверьте поиск контрагента по ИНН.
  9. Установите штатный «Коннектор к 1С» и настройте сопоставление стадий.
  10. Только после проверки включите запись в 1С с предпросмотром.
  11. Для Grok на сайте нужен публичный адрес. Откладывайте этот шаг до защиты сервера.
